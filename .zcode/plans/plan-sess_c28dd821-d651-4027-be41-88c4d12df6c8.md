# Auto Name-Position Detection for Certificate Templates

## Architecture (per spec)
OCR runs **client-side, once per template, admin-only**. Student download path never runs OCR — it fetches a saved normalized region from Supabase and uses cheap pdf-lib math. Zero new dependencies (`tesseract.js@7.0.0` already installed).

## New files

### 1. `lib/templateTypes.ts` — shared interfaces
```ts
OCRLine { text, x, y, width, height, confidence }        // pixels, TOP-LEFT origin
NameRegion { x, y, width, height, centerX, centerY, confidence, upperLine?, lowerLine? }  // pixels
GapCandidate { gapTop, gapBottom, gapHeight, score, upperLine, lowerLine, scores: {gap, position, alignment, confidence} }
SavedNameRegion { version:1, method:'auto'|'manual', centerX:number|null, centerY:number, confidence:number|null, imageWidth, imageHeight, savedAt }
```
Documented coordinate system: **SavedNameRegion is normalized 0–1, image space, top-left origin** (`centerY = centerPx / imageHeight`). Resolution-independent; maps to PDF page by fraction with Y inverted at draw time (image drawn full-bleed on A4 landscape 841.89×595.28).

### 2. `lib/ocr.ts` — Tesseract.js wrapper (client-only)
`analyzeTemplateImage(file: File|Blob, onProgress?)` → `{ lines: OCRLine[], imageWidth, imageHeight }`.
- `await import('tesseract.js')` (dynamic — never runs during SSR; spec requirement)
- `createWorker('eng')`, `setParameters({ user_defined_dpi:'300', tessedit_pageseg_mode: PSM.AUTO })`
- `recognize(file, {}, { blocks: true, text: true })` → traverse `data.blocks[].paragraphs[].lines[]`, convert `bbox{x0,y0,x1,y1}` → `{x,y,width,height}`
- Progress via `logger` option → `onProgress({status, progress})`; single worker, `terminate()` in `finally`
- Image dimensions: decode via `createImageBitmap` (or Image element) for normalization
- Errors surfaced as typed messages (init fail, no blocks, non-image) — never throws raw

### 3. `lib/namePositionDetector.ts` — deterministic geometry (no ML, no OpenCV)
`detectNameRegion(lines, imageWidth, imageHeight, options?): NameRegion | null` — options `{padding=0.15 (fraction of gap), minGap=0.02, maxGap=0.45}` (normalized to image height).
Algorithm:
1. Sort lines by y; drop noise (confidence<40, width<3% of image, degenerate boxes)
2. Consecutive-line gaps: `gap = lowerLine.top − upperLine.bottom`
3. Filter by minGap/maxGap; require both lines non-degenerate
4. Score each candidate (0–1 components, weighted sum):
   - **gap 0.45** — larger gap = higher (capped at maxGap; excessive-gap penalty beyond 0.6·H)
   - **alignment 0.25** — |upper.centerX − lower.centerX| small AND near image center → name likes centered surroundings
   - **position 0.15** — upper-middle band (gap center at 25–65% of height) preferred; edge penalty near top/bottom
   - **confidence 0.15** — mean OCR confidence of the two flanking lines
5. Best candidate wins (largest *reasonable* gap, not absolute largest). Region = gap center ± padding; `centerX` = midpoint of flanking-line centers.
6. Return `null` if no valid gaps or best score < 0.25 (low-confidence threshold).
Also exports `scoreGapCandidates(lines, w, h, options?): GapCandidate[]` for the debug UI (ranked scores).
No reliance on underlines/separators/specific phrases — pure geometry.

### 4. `app/api/save-name-region/route.ts`
POST `{ password, region }` → `verifyAdminPassword` + `adminRateLimiter` (same pattern as other admin routes) → validate JSON shape server-side (centerY∈[0.05,0.95], centerX null or [0,1], method enum, numbers only) → upsert `settings(key='template_name_region')`. No schema change — `settings.value` is TEXT.

### 5. `app/dev/name-detection/page.tsx` — debug/test playground (unlisted)
Client-only page: upload any PNG/JPEG → shows OCR lines (green boxes + text + confidence), ranked gap candidates with component scores, selected region (blue box), overall confidence. Used to run the spec's 8 test scenarios (original template / large blank space / no horizontal line / multiple decorative areas / footer+logo / long name / different resolution / portrait). Pure client-side analysis, no secrets, no DB writes.

## Modified files (minimal edits)

### `lib/generateCertificate.ts`
- `GenerateCertificateOptions` += `nameRegion?: SavedNameRegion | null`
- Replace hardcoded `const y = pageHeight * 0.455`:
```ts
const y = nameRegion?.centerY != null
  ? pageHeight * (1 - nameRegion.centerY) - fontSize * 0.35  // image top-left → PDF bottom-left Y inversion + BASELINE adjustment (drawText y = baseline, not visual center)
  : pageHeight * 0.455;                                        // FALLBACK ONLY (original template, no saved region) — clearly marked
```
- X: `nameRegion.centerX != null ? pageWidth*centerX - nameWidth/2 : (pageWidth-nameWidth)/2` (default stays centered)
- Gap-fit font cap: if region present, also shrink fontSize (min 26) so `fontSize*1.6 ≤ region height in pt` (prevents name overlapping flanking text on tight templates; no effect on original template's generous gap)
- Everything else (fetch/embed/font/auto-shrink/centering/draw/download) untouched

### `app/admin/page.tsx`
- After successful upload: auto-run `analyzeTemplateImage` on the uploaded File (progress bar from logger) → `detectNameRegion` → **auto-save if confident** via `/api/save-name-region`; show result inline
- Template preview becomes overlay-capable: wrap `<img>` in relative div, absolutely-positioned divs using % (= normalized coords): blue detected-region rect, green flanking-line rects, confidence badge
- Detection details panel: line count, top candidates w/ scores, selected region
- Manual fallback (detection null OR score<0.25 OR admin clicks "Adjust"): exact spec message *"Automatic name-position detection was not confident enough. Please manually set the name position."* + click-on-preview-to-set-point (computes normalized coords from click position; numeric X%/Y% inputs fine-tune) + Save
- On login, if a saved region exists (`/api/admin-login` returns it), show its overlay on current template
- "Re-analyze" button (avoids repeat OCR only when config already exists — spec perf rule)

### `app/page.tsx`

### `app/api/admin-login/route.ts`

## Error handling (never crash)
OCR init fail / unsupported image / no OCR lines / no valid gaps / low confidence / malformed bboxes / tiny or huge images → typed error messages shown to admin with retry; student path fully guarded: invalid/missing region → legacy 0.455 fallback.

## Constraints honored
No Python/Docker/external OCR/AI APIs/OpenCV.js/server-side OCR. No schema redesign. No changes to verification, auth, RLS, upload/Excel, font, headers, download naming. Only `tesseract.js` client-side.
